6. Donor profiles now retain completed/cancelled/failed enrollments alongside active ones and can expand each enrollment’s recorded timeline, including completed steps, failures and created tasks. 7. Fixed bounded due-task and pledge scans so already-fired records cannot permanently block items beyond the first 100. Existing audit deduplication remains. A failed batch retries before advancing. Notification persistence is reused; this does not reconstruct absent legacy records or assign Rebecca access to other users’ notifications.
8. Dashboard exposes the existing persistent donor notification feed, including overdue workflow alerts, with one-day/one-week snooze and dismiss. These actions update alerts, not underlying task completion. All-reminder and all-task links are available. Mailing deadlines are not yet produced.

9. Added matching-label downloads beside each prepared preview PDF part and each production PDF part. Production labels resolve the exact ordered generated letter IDs in the server tenant scope, preserving repeated recipients when different letters go to the same contact. Missing letters/contacts, suppressions or missing street addresses reject the entire matched label export; an override cannot silently change counts. Label-position and alignment-guide controls support partially used Avery 5160 sheets. Production generation now restores requested recipient order; standalone label selections retain list/selection order. Removed the 100-letter UI truncation: all generated IDs are partitioned into explicit 500-letter PDF parts with matching label controls. PDF exports reject missing requested letter IDs. No durable cross-session batch archive/address snapshot is introduced.
11. Contact letter history now exposes generated, printed, mailed and email-sent dates from existing persisted fields and can show all 100 loaded records rather than hiding everything after eight. This improves prospect outreach review but is not a new campaign mailing ledger or delivery proof.

UI polish follows the preferred letters/email command-workspace style: Segoe UI, neutral backgrounds, thin dividers, flat surfaces, restrained corners, compact toolbars, visible selection and focus. Existing accent preferences, controls, routes and reduced-motion behavior remain. Donor styling is scoped away from Events and Compassion shells.
