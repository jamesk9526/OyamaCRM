# Create labels and PDF preview verification

The Create label maker is available at `/oyama-create/labels`, through the sidebar, editor menu and settings shortcut. The previous Create tool URL resolves to the same component. Standalone label navigation points to Create. The shared recipient selection, eligibility, suppression override and ordered Avery renderer are retained.

Sheet defaults are saved explicitly per account, organization and browser. They include start position and guide visibility. Each suppression override requires its existing explicit confirmation.

## Evidence

- Desktop and phone layouts were inspected at 1600 × 950 and 430 × 790. The recipient table scrolls inside its own container. The page stays within the viewport width. See [desktop](labels-1600.png) and [phone](labels-430.png).
- Browser checks used fictional recipients and intercepted authenticated API responses, with PDFs generated by the actual Avery renderer. Two recipients starting at position 30 produced two US Letter sheets. PDF.js rendered the main page and thumbnails. Downloaded PDF bytes matched the displayed PDF exactly. Changing sheet settings disabled the stale proof print action. Explicit defaults survived reload. See [checks](checks.json).
- The classic Letter browser regression also passed at 1600 × 950, 1280 × 780, 900 × 720 and 430 × 790. It exercised the shared PDF viewer inside the editor, page navigation, dock controls, undo/redo, channel conversion and saved-draft rollback. See [letter proof](letter-proof/desktop-proof.png) and [browser assertions](letter-proof/browser-checks.json). Its PDF is synthetic.
- Twelve unit checks passed for Avery metrics and page continuation, audience resolution, suppression and incomplete-address eligibility, and opening the original PDF for printing.
- Web and server type checks and changed-file ESLint passed. PDF.js preparation copied its worker, standard fonts, character maps and decoding resources.
- Label styles are scoped to the label maker. PDF canvas geometry is scoped independently from app image styling. Editor scrollbar and proof chrome rules target v5 panels, with document typography handled by the existing renderer.
